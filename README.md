# Конвертер архивов ТМИ

Библиотека и консольные программы для преобразования двоичного файла
архива исходной ТМИ (формат из документа «Структура архивов — предложения
НПО ИТ») в формат архива ССПП ТМИ (п. 3 документа «Протокол и структура
архива ССПП ТМИ»).

Каждый пакет исходного файла превращается в пакет ССПП типа **INFO**, в начало
результата записывается пакет **FILE_HEADER**. Пакетов других типов в
результате нет.

## Структура проекта

```
tmi-converter/                 родительский pom (packaging = pom)
├── tmi-converter-lib/         библиотека
│   └── ru.example.tmi
│       ├── TmiConverter         конвертация InputStream → OutputStream и Path → Path
│       ├── ConversionResult     статистика конвертации
│       ├── DotNetTicks          .NET DateTime.Ticks (ДМВ) ↔ Instant (UTC)
│       ├── Ipv4Address          адрес IPv4 (единственное место с порядком байтов адреса)
│       ├── TmiFormatException   базовое исключение формата (+ наследники)
│       ├── source/              исходный формат: SourcePacket, SourcePacketReader, SourcePacketWriter
│       └── sspp/                формат ССПП: SsppInfoPacket, SsppProperty, SsppWriter
├── tmi-converter-cli/         консольный конвертер (tmi-converter.jar)
├── tmi-generator-cli/         генератор тестовых входных файлов (tmi-generator.jar)
│                              и сквозной тест генерация → конвертация → разбор
└── docs/                      исходные документы (не входят в репозиторий)
```

## Сборка

Требуются JDK 8 или новее и Maven 3.6+. Внешних зависимостей, кроме JUnit 5
для тестов, нет.

```
mvn clean verify
```

Код совместим с Java 8: на JDK 8 компилируется с `source/target 1.8`, на JDK 9+
с `--release 8`. Сборка создает исполняемые jar со всеми зависимостями:

- `tmi-converter-cli/target/tmi-converter.jar`
- `tmi-generator-cli/target/tmi-generator.jar`

## Запуск

Генерация тестового файла:

```
java -jar tmi-generator-cli/target/tmi-generator.jar test.bin --packets 20 --seed 42
```

- `--packets N` задает количество пакетов (по умолчанию 20);
- `--seed S` задает зерно генератора: при одинаковом зерне файлы совпадают
  побайтово. Если зерно не указано, оно выбирается случайно и печатается.

Конвертация:

```
java -jar tmi-converter-cli/target/tmi-converter.jar test.bin test.sspp
```

При успехе программа печатает количество сконвертированных пакетов и
возвращает код 0. При ошибке выводит в stderr одну строку с описанием и
смещением проблемного пакета и возвращает ненулевой код: 1 означает ошибку
формата или ввода-вывода, 2 означает неверные аргументы. Частично записанный
выходной файл при ошибке удаляется.

Использование библиотеки:

```java
ConversionResult result = new TmiConverter().convert(Paths.get("in.bin"), Paths.get("out.sspp"));
```

## Соответствие полей

Исходный пакет (Little Endian):

| Смещение | Байт | Поле           | В формате ССПП |
|----------|------|----------------|----------------|
| 0        | 4    | Marker         | проверяется (`0x551CBEA7`), при несовпадении ошибка |
| 4        | 4    | SrcIPv4Address | свойство `SOURCE_IP` (код 0) |
| 8        | 4    | DstIPv4Address | отбрасывается: в ССПП нет такого поля (см. примечание к табл. 6 документа) |
| 12       | 2    | SrcPort        | свойство `SOURCE_PORT` (код 2) |
| 14       | 2    | DstPort        | «Номер источника» и свойство `DESTINATION_PORT` (код 1) |
| 16       | 4    | DataLength     | длина Data во входном файле |
| 20       | 4    | Counter        | отбрасывается: в ССПП нет такого поля |
| 24       | 8    | Timestamp      | «Время приема» (`Instant`, UTC) |
| 32       | 4    | Flags          | бит 0: Data сжата zlib, при конвертации разжимается |
| 36       | n    | Data           | «Данные» (`ShortByteArray`) |
| 36 + n   | 4    | Checksum       | читается и игнорируется |

Пакет INFO (Big Endian):

| Поле                | Тип               | Значение |
|---------------------|-------------------|----------|
| Сигнатура, тип      | 4 + 1 байт        | `SSPP`, `0x00` |
| Тип источника       | `VeryShortString` | `UDP` |
| Номер источника     | `UShort`          | DstPort |
| Время приема        | `Instant`         | секунды (`Long`) + наносекунды (`Int`) с 1970-01-01 UTC |
| Данные              | `ShortByteArray`  | Data (разжатая, если Flags & 1) |
| Количество свойств  | `Byte`            | 3 |
| Свойства            | код, длина, значение | `SOURCE_IP` (4 байта a.b.c.d), `DESTINATION_PORT` (`UShort`), `SOURCE_PORT` (`UShort`) |

FILE_HEADER: `SSPP`, `0x80`, затем `ByteArray` с телом `Version`:
`00 00 00 04 00 01 00 02` (длина 4, версия 1.2).

## Преобразование времени

`Timestamp` содержит .NET `DateTime.Ticks`, то есть количество 100-нс
интервалов с 0001-01-01 00:00, записанное в ДМВ (UTC+3):

```
UNIX_EPOCH_TICKS = 621 355 968 000 000 000    // 1970-01-01 00:00 в ticks
MSK_OFFSET_TICKS = 3 × 3600 × 10 000 000      // 3 часа

unixTicks = ticks − UNIX_EPOCH_TICKS − MSK_OFFSET_TICKS
seconds   = floorDiv(unixTicks, 10 000 000)
nanos     = floorMod(unixTicks, 10 000 000) × 100
```

`floorDiv`/`floorMod` дают корректный результат и для моментов до 1970 года:
наносекунды всегда неотрицательны, как требует `Instant`.

## Принятые допущения

1. **Порядок байтов IPv4-адресов.** Все поля исходного формата формально в
   Little Endian, но адрес `a.b.c.d` считается записанным как 4 байта подряд
   в сетевом порядке (`a` в первом байте). Он копируется как есть, без
   разворота, и так же пишется в свойство `SOURCE_IP`. Допущение
   сосредоточено в классе `Ipv4Address`.
2. **ДМВ = UTC+3** без переходов на летнее время.
3. **Сжатие.** Если `Flags & 1 == 1`, Data разжимается (zlib, `java.util.zip.Inflater`)
   и в «Данные» пишется разжатое содержимое, то есть пакет «в том виде, в
   котором он был получен». `DataLength` в этом случае относится к сжатым
   данным. Остальные биты `Flags` не определены форматом и сознательно
   игнорируются (константа `TmiConverter.KNOWN_FLAGS`).
4. **Ограничение 65535.** Длина «Данных» в ССПП имеет тип `UShort`. Если Data
   (после разжатия) длиннее 65535 байтов, конвертация прекращается с ошибкой.
   Разжатие останавливается, как только превышен этот предел, что заодно
   защищает от zip-бомб.
5. **Защита от поврежденной длины.** Читатель исходного формата отвергает
   `DataLength` больше 1 МиБ, не пытаясь выделить под него память. Это с
   большим запасом покрывает максимальный размер UDP-пакета.
6. **Потоковая обработка.** Файл читается и пишется пакет за пакетом через
   буферизованные потоки; в памяти находится только текущий пакет.
7. **Версия формата 1.2**: последняя в таблице истории изменений документа
   ССПП. Свойство `TRANSIENT` (добавлено в 1.2) не используется: такие пакеты
   в архив не пишутся.
8. **Тип источника** всегда `UDP`: по документу ССПП НИПы передают ТМИ по
   UDP, и номером источника для этого типа является порт получателя.
9. **Ошибки.** Все ошибки формата являются наследниками
   `TmiFormatException extends IOException` и содержат смещение начала
   проблемного пакета: `InvalidMarkerException`, `TruncatedPacketException`
   (обрыв в заголовке, Data или Checksum), `DataTooLongException`,
   `DecompressionException`. Пустой входной файл ошибкой не является:
   результат содержит только FILE_HEADER.
10. **Генератор** пишет в Checksum значение Adler-32 от Data (в документе
    указано «CRC32-Adler»); конвертер его не проверяет.

## Тесты

`mvn clean verify` запускает:

- `DotNetTicksTest`: известные даты, пример из документа ССПП, время до 1970
  года, доли секунды, сверка с `java.time`;
- `SourcePacketReaderTest`: разбор пакета, собранного вручную побайтово,
  несколько пакетов подряд, неверный маркер, обрыв файла после каждого
  байта пакета, пустой файл;
- `SsppWriterTest`: побайтовое сравнение с разобранным примером пакета из
  п. 3.1 документа ССПП и с FILE_HEADER;
- `TmiConverterTest`: соответствие полей, сжатые данные, неизвестные флаги,
  длина больше 65535 (в том числе после разжатия), поврежденный zlib,
  игнорирование Checksum, удаление частичного результата;
- `EndToEndTest` (модуль генератора): генерация → конвертация → разбор
  результата собственным парсером теста и сравнение всех полей;
- тесты консольных программ: аргументы, коды возврата, сообщения без stack trace.
